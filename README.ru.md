# Multi (`multi`)

[English →](README.md) · [中文 →](README.zh.md)

спроси две-три модели сделать одно и то же, ревью и ответы выходят получше.

| команда | что делает |
|---|---|
| `/multi:code-review` | ревью кода суб-агентами Claude + Codex + OpenCode, а Claude Code (!) сводит всё в один отчёт |
| `/multi:check-if-done` | работа реально доделана или только выглядит доделанной, каждое "«"готово"»" подтверждено реально запущенной командой |
| `/multi:ask` | задаёшь один вопрос всем сразу и смотришь три ответа рядом. никто не судит, никто не проверяет |

## README по-человечески

как не трудно догадаться, это использование трёх моделей вместо одного на:

1. `/multi:code-review` - ревью кода саб-агентами Claude, запросом к Codex (через headless exec) и headless-запросом к OpenCode + линза [ponytail](https://github.com/DietrichGebert/ponytail) на оверинжиниринг. глянь описание плагина ponytail, штука прикольная
2. `/multi:check-if-done` - та самая "а задача точно готова??? перепроверь!!!!". модель, которая только что написала код - худший судья того, работает ли он, поэтому тут спрашиваем те модели что не писал этот код, и ничего не зовём готовым, пока реально не прогоним команду, которая это докажет. должно чинить случаи "ой извини я поспешил с выводами ЛОООЛ"
3. `/multi:ask` - просто спроси у всех одно и то же и получи три ответа. три ответа, без слияния, без судейства

установка
```bash
claude plugin marketplace add szarkans/multi-code-review
claude plugin install multi@szarkans-skills

или
npx skills add szarkans/multi-code-review

или
git clone https://github.com/szarkans/multi-code-review ~/.claude/skills/multi
```

потом перезапусти claude code и в целом просто попроси его всё настроить и всё. там кодекс логин, опенкод + модель в нём и т.д., клауд разберёстя сам
